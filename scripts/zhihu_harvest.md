# 知乎问题矿源（2026-08-18 起，Jack：「最大化去找最多的问题，核心是流量最大化」）

## 三个矿口，按价值排序

| 入口 | URL | 为什么值钱 |
|---|---|---|
| **邀请回答** | `zhihu.com/question/waiting?type=invite` | 知乎主动派给我们的，说明账号已进法律话题图谱。**优先级最高** |
| **最新问题** | `zhihu.com/question/waiting?type=new` | 0-2 个回答的新题，抢首答＝永久占坑。**时效性强，当天不答就被别人占了** |
| 为你推荐 | `zhihu.com/question/waiting` | 算法推的，量大但杂 |
| **搜索** | ⛔ **别用 `zhihu.com/search` 页面**（DOM 抓不到题，见下）；走 `/api/v4/search_v3` | **2026-09-06 实测产能最高的一口**：12 个词 → 104 条去重 → **87 条 <30 未答（可用率 84%）**，且全是长青咨询题，**不像 new 口那样过夜腐坏** |

## 采集脚本（在已登录的 Chrome 里跑）

```js
const m={};
document.querySelectorAll('a[href*="/question/"]').forEach(a=>{
  const q=(a.href||'').match(/question\/(\d+)/);
  const t=(a.innerText||'').trim();
  if(q&&t.length>6&&!m[q[1]])m[q[1]]=t.slice(0,42);
});
JSON.stringify({n:Object.keys(m).length,list:m})
```

⚠️ **别从列表页读浏览/回答数** —— 卡片 DOM 嵌套不稳，`closest()` 会串到相邻卡片，
实测 20 条全被写成第一条的 36,608/462。**要真数只能逐个开问题页读。**

## 🔓 搜索口（2026-09-06 新开，产能最高，优先走这口）

**搜索结果页的 DOM 抓不到题** —— 实测整页只有 56 个 `<a>`、0 条 `/question/` 链接，
结果是懒渲染的，`document.querySelectorAll('a')` 那套采集脚本在这一口上**返 0 不是没题**。
可用路径是 API：

```js
// 在已登录 Chrome 的 zhihu.com 上下文里跑
const r = await fetch('/api/v4/search_v3?t=general&q='+encodeURIComponent(kw)
                      +'&correction=1&offset=0&limit=20&show_all_topics=0');
const j = await r.json();
(j.data||[]).forEach(d=>{ const o=d.object||{};
  // 注意：结果既有 answer 也有 question，两种取法不同
  if(o.type==='answer'  && o.question) { qid=o.question.id; title=o.question.name||o.question.title; }
  if(o.type==='question')              { qid=o.id;          title=o.name||o.title; }
});
```

拿到 qid 后**必须逐个打 `/api/v4/questions/{qid}/answers?limit=1` 读 `paging.totals`** 才有精确答数
（列表页的答数一律不可信，见上面那条警告）。同一批里顺手读 `is_mine` 防撞车。

### 为什么这一口值钱：它的题不腐坏

| 矿口 | 单次产出 | 可用率 | 题的性质 |
|---|---|---|---|
| invite | 20 条 | 09-06 只剩 4 条 | 已见底 |
| new | 20 条 | **15%** | **新闻钩子，过夜必腐坏** |
| recommend | 20 条 | 7 条真咨询，ES 全打不动 | 混杂 |
| **search_v3** | **104 条去重** | **84%（87/104）** | **长青，答数增长慢，不腐坏** |

银行稿最大的成本是过夜腐坏（答数冲过 30、点名答主被顶下去、开场答数自述过期）。
search_v3 捞的是"欠钱不还起诉流程""交通事故误工费怎么算"这类**常年有人搜的长青题**，
答数几个月才动一位数 ⇒ **银行稿可以放心攒两三天**，这是它相对 new 口的结构性优势。

### 反向匹配打法（比"先有题再找数据"高效得多）

先挑一条**已验证纯度达标**的数据链，再用该案由的口语说法去搜题。
09-06 实测：`q=借条 × 民间借贷纠纷 = 96%`、`q=增值收益 × 离婚后财产纠纷 = 85%`，
拿这两个案由的口语词去搜，一次就搜出十几道 <30 的对口题。
反过来（先看到题再试案由）当天连废四条链：房产借住族、劳务派遣族、装修族、假货族。

**搜索词就用当事人的原话**，别用法言法语——法言法语搜出来的是同行写的科普，不是求助帖。
已验证好用的 12 个：欠钱不还起诉流程／借条过了三年／交通事故误工费／对方全责保险不赔／
父母房子继承兄弟姐妹／遗嘱无效／离婚婚前房子怎么分／离婚一方转移财产／公司不给加班费／
被执行人没有财产／装修公司跑路／买到假货怎么赔。

## 选题优先级（2026-08-18 定）

1. **邀请回答里的产品对口题** —— 例：「类案检索中如何提高检索效率」，这是知乎把我们的
   目标关键词直接送上门
2. **新题抢首答**（回答数 0-2，发布 < 24h）—— 占坑成本最低
3. **真实案例咨询**（回答数 < 10）—— 能用真数据答
4. 工具选型题 —— 只能讲方法，垫底

**永远不碰**：时政/娱乐/股票新股这类高热但与我们无关的（新题列表里一半是这些，直接跳过）。

## 案由轮换

见 PLATFORM-PLAYBOOK「案由轮换」那张基线表。同一案由连答会让数据雷同，
每个案由答 2-3 个就换，并且**每答一个新案由就往基线表加一行** —— 那张横向对比表
是别人给不出的东西（他们只有法条，没有分布）。
