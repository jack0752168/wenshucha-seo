# 文书查 SEO：MCP 付费获客路线（2026-10-30 起）

## 决策与目标

Jack 明确要求文书查 SEO 重点推广 MCP；当前付费用户来自 MCP 产品线。最终结果是可归因的 MCP 新付费客户、续费和收入。访问、发文、搜索展现、公开 Key 握手、免费检索使用和申请表提交都是中间信号，不等于收入。本文件只管文书查/SinoVerdict；JackTrader 不在此范围。已上线的免费检索与研究报告保留服务和基本健康维护，可作数据能力佐证；新选题、内链和 CTA 以 MCP 为主。

## 客户与主张

1. 法律 AI 厂商／开发者：把中国裁判文书接入已有 Agent、RAG 或产品。提供公开 Key、接入示例、可复现返回和 Pro 开通路径。
2. 有自建 AI 工作流的律所／企业法务：需要可追溯的判例检索、案号／判词核验和团队使用。提供真实工作流演示，再进入团队版或机构申请。
3. 采购与合规负责人：关心数据覆盖、缺口、授权边界、稳定性和报价。提供技术与数据说明及机构申请入口。

四工具是 `search_judgments`、`get_judgment`、`verify_case_number`、`verify_quote`。必须如实写 BM25 词汇检索，不能写成向量语义；1.6 亿是记录数，不是独立案件数。正文覆盖、无原始文书直链等限制按现网页面说明。价格与额度只取 `~/wsc-mcp/src/keys.mjs` 的 `PLANS` 并核现网，不由 SEO 改价。

## 搜索与内容

- 接入：裁判文书 MCP、法律判例 MCP、Claude/Cursor 接入裁判文书、法律 AI 数据接入。
- 选型：判决书全文 API、法律案例检索 API、法律 RAG 数据源、法律 MCP 服务比较。
- 核验：AI 编造案号怎么查、判词引用核验、判决书真实性校验。

每题先核真实搜索需求、竞品页面与现有页是否抢词。优先修现有 `/mcp/`、`/mcp/quickstart/`、`/pricing/`、`/mcp/apply/` 的标题、示例、移动端、CTA、内链和索引。新内容一周最多两页；只有能展示真实调用、参数、返回样本和局限时才发布。不按数量凑泛法律咨询或学生论文流量。知乎仅答与法律数据接入、MCP 集成、核验相关的真实提问；遵守原配额、去重和发布核验。

内容主 CTA 是「用公开 Key 跑一次真实调用」；机构采购类内容指向机构申请。CTA 落到合适入口并带可识别来源标记。免费检索或研究报告不作为付费 MCP 的替代成交页，不虚构法院原文链接。

## 漏斗与日报

按完整日、相同口径记录：

1. MCP 入口有效访次及来源；剔除已知机器人、自访和 QA，无来源不猜成知乎或百家号。
2. 公开测试 Key 的真实工具调用及调用人数估计；`initialize`、`list_tools`、目录探活不算使用。共用 Key 无法精确归因到个人或渠道，须写 `unknown`。
3. 新独立 Key 数、独立 Key 首次真实调用、七日内再调用。
4. 机构申请的服务端实收回执、合格需求、联系进展。
5. 已核实付款和续费；没有收款证据写未核实。咨询、表单或微信点击不是成交。

每周检查来源→测试→独立 Key→有效调用→付费的断点。入口有流量但没人调用，先修接入与可靠性；有调用但没人转独立 Key，查额度与 CTA；有申请但没付款，查需求匹配与交付摩擦。只有断点证据才改页面。日报不以发文数或推送受理数报成绩。

## 30 天顺序

1. 第一周：核 `/mcp/` 至公开 Key 的真实首调、四个入口和移动端；确认来源及申请回执可回读，记录基线。公开端点不可用不能当成客户没意愿。
2. 第二周：优化现有快速接入和真实返回示例；对准一个接入词组，不同时改多个页面标题。
3. 第三周：做一组「检索→取全文→核验」可复现实例，实测页面到首调及独立 Key 开通。
4. 第四周：依据成熟搜索数据和真实漏斗，保留有效词、停止低意图词，再决定第二个主题。

律所采购周期长，30 天零付款不能直接证明 SEO 无效；免费调用量也不能当付费需求。公开 Key 共享额度和 MCP 端点的本地隧道依赖会污染实验，分析时单列。客户方案和报价由现有业务规则及 Jack 决定。
