# 类案检索怎么搜得准？六个漏检来源与一套可复用的检索式搭法，律师可套用清单

类案检索搜不准，是律师办案里最消耗时间、也最难自己发现的一件事。搜错了你知道，搜漏了你不知道——直到开庭时对方甩出一份你没见过的同类判决。这篇不谈检索系统的功能罗列，只讲一件具体的活：给定一个待办案件，怎么把同类案件撈得又全又准，以及怎么判断自己"撈全了"。文末给一份可以直接照着走的检索式搭法和一份自查清单。

先给一句结论：类案检索的准，靠的不是找到一个"神级关键词"，而是靠一套能自我修正的迭代流程——先把法律问题界定对，再用多层检索式把案件池撈出来，然后用停止信号验证有没有漏。把检索当成一次性的"输入关键词、拿结果"，注定要漏；把它当成三轮迭代的收敛过程，才撈得住。

## 一、先分清两种"搜不到"

律师说"搜不到类案"，其实是两件完全不同的事，处理方法也完全相反。

**第一种：库里确实没有。** 新型案由、新出台的司法解释适用、极小众的争议点，全国范围内可能确实还没有形成足量的同类裁判。这种情况下，再怎么调检索式也撈不出来——正确的动作是承认它，转而去找**相邻问题**的裁判思路（比如上位法条的适用逻辑、类似法律关系的处理），而不是继续在原关键词上打转。

**第二种：库里有，你没撈上来。** 这才是绝大多数情况，也是这篇要解决的问题。案件就在那儿，但你的检索式和判决书实际的用词、结构对不上，于是它们落在你的结果页之外。

区分这两种有个笨办法很有效：**把检索条件故意放到极粗**（只留罪名或案由 + 最核心的一个法条），看总量。放粗之后有成千上万篇，说明库里不缺案子，是你撈的方法有问题；放粗之后总共也没几十篇，那可能真是第一种。先做这一步，能省下大量在错误方向上的时间。

## 二、漏检的六个来源

下面六条，是把"库里有你没撈上"拆开之后的具体成因。按发生频率排，前三条是重灾区。

### 1. 法律问题界定得太粗或太窄

这是很常见的一类漏检来源，而且它发生在打开检索系统之前。

**界定太粗**："我要搜劳动争议的类案。"——劳动争议底下有几十个截然不同的争议焦点，撈回来彼此不可比，等于没撈。
**界定太窄**：把本案事实细节直接当检索条件，条件叠得太死，真正可比的案件被挡在外面。

正确做法是先把本案抽象成**一个可检索的法律问题**：争议焦点是什么、适用哪条法条的哪一款、双方争的是构成要件的哪一个环节。界定做对了检索式自然就出来；界定错了，后面每一步都在放大错误。

### 2. 你用的是当事人的话，判决书用的是法院的话

当事人跟你说"公司让我签了个东西然后把我辞了"，判决书上写的是"解除劳动合同的程序是否合法"。你用前一套词去搜，撈不到后一套词写成的文书。

**检索用词必须切换成裁判文书的书面表述。** 同一个意思，法院可能写成"未尽到审慎审查义务""不构成表见代理""案涉款项性质应认定为借款"——这些才是能命中的词。一个实用技巧：先随便撈几篇明显同类的判决，**读它们的"本院认为"部分，把法院的原话摘出来当作下一轮的检索词**。这一步几乎总能让召回量上一个台阶。

### 3. 只搜关键词，不搜语义

同一个法律问题，不同法院、不同年份的表述可能完全不重合。纯关键词匹配的检索，命中的是"字面写了这几个字"的文书；语义检索命中的是"讲的是这件事"的文书。两者撈回来的案件集合有相当一部分是不重叠的。

实操上不必纠结原理，只需记住一条：**关键词检索和语义检索都跑一遍，取并集**。关键词那一路负责精确命中法条、术语、案号这类硬信息；语义那一路负责把表述不同、意思相同的判决捞回来。只用其中一种，就等于放弃另一半。

### 4. 检索范围没有分层收敛

一上来就把地域、审级、年份全部锁死，是另一种常见的自伤。

正确的顺序是**先放开、后收敛**：第一轮全国范围、不限审级，目的是看清这类问题的整体裁判格局和主流观点；第二轮再按你的实际需要收敛——要说服本地法院就收到本省本市，看清上级尺度就收到二审和再审。**收敛必须发生在你已经看过全局之后**，否则你根本不知道自己收掉了什么。

反过来也有个坑：只看本地。本地同类案件如果只有个位数，那点样本得出的"本地裁判倾向"是不可靠的，容易把偶然当规律。

### 5. 只看文书开头，不看"本院认为"

这一条很少有人讲，但对检索质量的影响极大。

**裁判文书的信息密度分布是极不均匀的。** 一份判决书的开头是当事人身份信息、诉讼代理人、程序沿革——对你判断这个案件是不是类案，几乎零价值。真正决定它可不可比的东西，是**"本院认为"往后那一段**：法院怎么认定事实、怎么适用法条、说理链条怎么走。而这部分往往在文书的中后段。

这带来两个实际后果：
- **看结果列表时**，只扫标题和摘要开头就判断"不相关"，会误杀大量真正的类案。判断可比性必须跳到裁判理由部分去看。
- **评估一套检索系统时**，要看它的相关性排序和摘要是不是基于裁判理由。只按文书开头字面匹配排序的，前面很可能堆着一批"名字像、说理不像"的案件。

### 6. 只做一轮，不做迭代

最后一条是流程问题：很多漏检本质上是因为检索只做了一轮。第一轮的检索式必然不完善——因为检索之前你还不知道法院是怎么表述这个问题的。第一轮的真正价值不是拿到结果，而是**拿到更好的检索词**。不做第二、第三轮，就等于用你最差的那版检索式定稿。

## 三、一套可复用的检索式搭法：四层 + 三轮

把上面六条反过来，就是一套可以照着走的流程。

### 检索式的四层结构

搭检索式时，把条件分成四层，逐层加，每加一层看一次结果量的变化：

- **争点层**：本案争议焦点的书面表述（法院用语）——决定撈回来的是不是同一个问题。
- **法条层**：具体到条、款的法律与司法解释依据——锁定裁判依据，排除表面相似。
- **术语层**：该问题下的固定裁判用语与同义表述——提高召回，覆盖表述差异。
- **边界层**：案由、审级、地域、时间——最后收敛，控制可比范围。

关键在**加的顺序**：争点层和法条层先加，术语层用来扩召回，边界层**永远最后加**。顺序反了，你会在还没看清全局时就把有用的案件筛掉。

### 三轮迭代

- **第一轮（探路）**：条件放粗，全国不限审级。目的只有一个——读回来的判决里的"本院认为"，摘出法院的原话。别急着做筛选。
- **第二轮（扩召回）**：把第一轮摘到的法院原话补进术语层，关键词与语义两路都跑，取并集。这一轮要的是"宁多勿漏"，池子大一点没关系。
- **第三轮（收敛）**：加边界层，按审级、地域、时间收到你实际需要的范围；逐篇核裁判理由，把"看着像、说理不像"的踢出去。剩下的才是你真正能用的类案。

三轮跑完，通常比一轮直接搜多撈出相当一批案件——而且多出来的那批，往往正是表述与你的直觉不一致、却恰恰最有参考价值的那些。

## 四、怎么判断自己"撈全了"：三个停止信号

检索没有绝对的完备，但有几个可操作的停止信号。三个都满足时，可以停。

**信号一：新增案件不再带来新的裁判观点。** 继续放宽条件、继续翻页，新撈到的案件说理都落在你已经归纳出的那几类观点里，没有出现第 N+1 种思路。这是最可靠的信号。

**信号二：反向检索能撈回你已有的案件。** 换一套完全不同的检索词（比如从法条切入改成从裁判用语切入），看能不能把手上的核心案例重新撈出来。撈得回来，说明覆盖面够；撈不回来，说明还有你没走过的检索路径，也就可能还有你没见过的案件。

**信号三：支持和反对的观点你都撈到了。** 如果你的结果里清一色支持你方立场，几乎可以肯定检索式带了偏。同一个法律问题在全国范围内出现对立裁判观点是常态，撈不到对立观点，通常不是因为没有，而是因为你的检索词天然只命中了一边。**这一条对办案的意义最直接**：对方会用的案例，你必须先看到。

## 五、检索式之外：撈回来之后怎么用

类案撈全了只是完成一半，剩下一半是把它变成能用的东西：

- **按裁判观点分组，不按时间排列。** 按"法院支持了哪种观点、理由是什么"归成几组，每组标注数量和典型案例。
- **每一个进入论证的案件都要能点回原文。** 二手转述、他人整理的摘要不能直接当论据——表述在转述中失真是常事。
- **对立观点单列一节**，并想好回应，这是检索报告里最有价值的部分。
- **留痕**：用了哪些检索式、哪一轮加了什么条件、筛掉了什么，便于复核与案件交接。

## 六、选型时该问的几个问题

如果所在律所正在看类案检索系统，不必陷进功能清单的对比，问清下面几件事就够判断：

1. **底座覆盖多大、能不能回链原文？** 每篇结果能否一键点回完整裁判文书原文，是可信度的地基。文书查这类系统提供的全量裁判文书底座（当前收录约 1.6 亿篇），价值就在于让"撈得全"有物理前提——池子里没有的，再好的算法也变不出来。
2. **支不支持关键词与语义两路检索？** 只有一路的，注定漏掉另一半。
3. **相关性排序基于什么？** 是全文字面匹配，还是能识别裁判理由部分。前者会把大量"名字像、说理不像"的案件排到前面。
4. **能不能按结构化条件筛？** 案由、法条、审级、审理程序、裁判结果能否叠加为条件，决定你能不能把池子圈干净。
5. **能不能做聚合分析、能不能留痕导出？** 前者决定你面对几百篇时是不是只能一篇篇翻，后者决定检索报告能不能直接成型、团队之间能不能复现。

## 七、可套用的检索自查清单

- [ ] **定问题**：本案抽象成一个可检索的法律问题了吗？争议焦点、法条到款、争的是哪个构成要件？
- [ ] **验库存**：条件放到极粗，看总量——是"库里没有"还是"我没撈上"？
- [ ] **换用语**：检索词是不是法院的书面表述，而不是当事人的口语？
- [ ] **第一轮**：全国不限审级探路，读"本院认为"摘法院原话
- [ ] **第二轮**：原话补进检索式，关键词 + 语义两路跑，取并集，宁多勿漏
- [ ] **第三轮**：加边界层收敛，逐篇核裁判理由，踢掉"说理不像"的
- [ ] **验停止**：新增无新观点？反向检索撈得回核心案例？对立观点撈到了吗？
- [ ] **成结论**：按裁判观点分组、对立观点单列、每篇可回原文、检索过程留痕

## 八、说到底

类案检索这件活，拉开差距的不是谁知道更多检索技巧，而是谁把它当成一个**可以自我验证的流程**在做。界定问题、切换用语、两路取并集、三轮迭代、用停止信号验证——每一步都很朴素，但少任何一步，漏检就会悄悄发生，而且你不会知道。

工具的作用是把体力活压下去：底座够全你才可能撈得全，排序认得出裁判理由你才不用翻十页，能聚合分析你才能从几百篇里快速看清观点分布。但界定法律问题、判断可比性、决定怎么用，仍然是律师的判断——工具只是把尺量准，落笔的还是人。
